# 仓库内容与隐私标准

## 允许提交

源代码、合成测试样本、锁文件、构建脚本、CI 工作流、许可证、公开使用文档，以及人工检查过的 docs/assets 宣传图片。示例必须使用虚构内容，不得从真实聊天裁剪后冒充合成样本。第三方许可证必须随构建产物保留。

## 禁止提交

真实对话、摘录、笔记、导出备份、诊断原件、个人路径、邮件、账号凭据、API 密钥、Cookie、浏览器配置、会话状态、网络抓包、内部任务记录、未经检查的截图。依赖目录、构建目录、ZIP、日志、缓存和覆盖率报告不进入源码仓库。ZIP 仅作为经过检查的 GitHub Release 附件。

## 每次提交

1. 使用明确路径暂存，避免盲目 git add .；运行 git status --short 和 git diff --cached --stat。
2. 运行 npm run check:publication：扫描 Git 跟踪文件和未忽略文件（含索引中的历史内容），拒绝未知路径、敏感文件和常见凭据。
3. 人工阅读 git diff --cached，复查图片、数据样本、网址及个人信息。自动扫描不能保证识别所有秘密。
4. 运行 npm run check、npm test、npm run build；必要时运行浏览器回归。
5. 推送后核对 CI。不得以跳过检查、强制添加忽略文件等方式解决检查失败。新增公开目录必须同时审查并更新 publication-check.mjs 白名单。

.gitignore 不会取消已经跟踪的文件。误跟踪应从索引移除并保留本地副本；秘密已经推送时，先撤销或轮换凭据，再协调清理历史，不能仅删除当前文件。不要在公开 Issue 中贴秘密作为排查证据。

## 版本与发布

产品使用数字语义版本；package.json、package-lock.json、manifest、隐私说明与三语 README 必须一致。弹窗与笔记库直接读取 manifest。数据 schema 独立维护。标签采用 v加版本号。升级前导出备份，保留原加载目录与扩展身份，避免卸载导致数据清除。

公开图片只允许放在 docs/assets，使用原创 SVG 或已审核的合成页面截图；README 可引用 Shields.io 技术栈徽章。不要使用带追踪参数或私人账户资源的图片。发布附件必须从干净输出目录构建，包含 LICENSE 和第三方许可，核对包清单和 SHA-256。
