# Markdown 总文档格式 · schema 1

文档是唯一持久内容源。设置和可重建索引不属于文档内容。所有记录的正文仅保存一次，避免外部编辑后被元数据里的旧副本覆盖。

## 分区

文档包含一个 library 块，后接多个 conversation 块。每个对话必须包含一个 note，以及零到多个 annotation。每块元数据为 UTF-8 JSON 的 Base64 编码，随后附上该 Base64 字符串的 SHA-256 校验值。结构化编码嵌在 `.md` 内，不是单独的 JSON 导出文件。

```text
<!-- dn:library BASE64 SHA256 -->
<!-- dn:conversation BASE64 SHA256 -->
<!-- dn:note BASE64 SHA256 -->
<!-- dn:body RECORD_ID -->
可编辑的 Markdown 正文
<!-- dn:endbody RECORD_ID -->
<!-- dn:annotation BASE64 SHA256 -->
<!-- dn:body RECORD_ID -->
可编辑的文字备注
<!-- dn:endbody RECORD_ID -->
<!-- dn:endconversation CONVERSATION_ID -->
<!-- dn:endlibrary -->
```

示例只说明结构，不能作为可导入文件。可读标题、摘录和“勿编辑”提示穿插在系统块之间。对话目录和批注目录的 ID 顺序必须与实际分区一致。

正文中以 `\` 或 `<!-- dn:` 开头的行在导出时额外加一个 `\`，导入时只移除这一层转义。用户从插件编辑器输入的类似系统标记不会误解析成系统字段。手工编辑导出文件时，新增类似系统标记的正文行也需要这一层转义。

UTF-8 BOM 和 CRLF 可接受，换行统一为 LF，正文保留空行及末尾换行。元数据校验不包含可编辑正文，因此合法编辑备注不会造成元数据校验失败。校验是损坏检测，不是加密、身份认证或防篡改签名。

## 必要元数据

- library：格式名、schema、库 ID、修订号、导出时间、导出范围、对话 ID 目录、删除标记。
- conversation：平台、稳定对话 ID、标题、规范化链接、批注 ID 目录。
- note：记录 ID、修订号、更新时间；正文单独存放。
- annotation：记录 ID、修订号、更新时间、颜色；原文锚点包含消息 ID、角色、消息文字 SHA-256、UTF-16 起止偏移、原选文及最多各 64 字符的前后文。备注正文单独存放。

当前实现要求页面提供稳定消息 ID；缺失时不创建持久批注。用户可手动重新关联变化后的原文，更新对应锚点。

## 导入语义

- 先严格解析、验证容量和目录，再生成预览；错误不会修改本地数据。
- 缺少的记录不表示删除。来自文件的删除标记不会自动删除本地记录。
- 未变化记录跳过；新记录默认选中导入；冲突、重叠、已删除记录默认保留本地，逐条确认。
- 重叠选择采用导入时，明确替换对应本地重叠记录，并保存删除标记。
- 预览记录当前库修订号；预览后库发生变化则拒绝提交，要求重新预览。
- 当前不支持部分损坏恢复或将任意 Markdown 作为笔记导入。

## 保存与迁移

扩展使用 `slot0`、`slot1` 和 `active` 指针。新版本写入非活动槽、回读比对并解析通过后切换指针；原活动槽成为恢复快照。指针切换失败时继续读取原活动槽。队列集中在 service worker 中，所有写入都由同一个入口执行。

schema 1 不需要历史格式迁移器。遇到未知 schema 拒绝写入，不自动清空。未来 schema 变化必须新增迁移器、旧样本测试和失败恢复路径，不能只修改常量。
